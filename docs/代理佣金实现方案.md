# 代理佣金 · 实现方案

配套规则见 `docs/代理佣金规则.md`。本文只讲怎么落地。

## 一、结论先行

**现有基础设施覆盖约七成,主要工作是一个结算钩子 + 一张流水表。**

| 需求 | 现状 |
|---|---|
| 邀请码 | ✅ `users.aff_code`,唯一索引 |
| 上级是谁 | ✅ `users.inviter_id`,有索引 |
| 绑定时间 | ✅ `users.created_at` —— 注册即绑定且不可更换 |
| 佣金余额 / 累计 | ✅ `users.aff_quota` / `aff_history` |
| 转成消费额度 | ✅ `TransferAffQuotaToQuota()`,前后端都有 |
| 按消费结算佣金 | ❌ **要开发** |
| 佣金流水 | ❌ **要开发**(核查期与提现审核都依赖它) |
| 人工提现扣减 | ❌ **要开发**(管理员目前无法调整 `aff_quota`) |

## 二、挂载点

`service/quota.go:414` 的 `PostConsumeQuota()`。每次请求结算后必经此处,且能拿到:

```
relayInfo.UserId            消费者

quota                       本次实际消费额
```

**只在这里加一次调用,不改任何现有逻辑。**

## 三、佣金计算

### 1. 利润基数

规则按「利润」计佣,但 new-api 只知道售价、不知道进货价。不建整套成本表,
用一个毛利率配置表,只列例外:

```json
{ "default": 0.60, "gpt-image2-4k": 0 }
```

```
利润 = 本次消费额 × 该模型毛利率
```

`gpt-image2-4k` 毛利仅 28%,设 0 即排除出返佣,避免它被佣金吃穿。
其余模型实测毛利 60~67%,取 0.60 偏保守,安全。

### 2. 直属代理佣金

按绑定时长(`now - user.created_at`)分三档:

| 时长 | 比例 |
|---|---|
| ≤ 7×24h | 50% |
| 7×24h ~ 1 年 | 15% |
| > 1 年 | 0,直接返回 |

```
直属佣金 = 利润 × 对应比例
```

### 3. 团队奖励(逐级 5%)

沿 `inviter_id` 继续向上,每级拿下一级佣金的 5%:

```
share = 直属佣金
for 上级 in 向上遍历:
    share = share × 0.05
    if share < 1: break        # 额度是整数,衰减到 0 自然终止
    给该上级记一笔
```

衰减极快:直属 ¥30 → 上一级 ¥1.5 → 再上一级 ¥0.075。**第三级起可忽略。**
仍设一个可配深度上限(默认 5)并记录已访问 id,防成环死循环。

## 四、新增数据表

```sql
affiliate_commissions
  id            主键
  user_id       收佣金的人(代理)
  from_user_id  产生消费的人
  log_id        对应的消费日志,便于追溯
  model_name    消费的模型
  level         1=直属,2+=团队奖励
  amount        佣金额度
  status        pending(核查期) / available(可提) / revoked(已冲销)
  created_at
```

索引:`(user_id, status)`、`(from_user_id)`、`(created_at)`。

**为什么必须有这张表:** 核查期判定、提现审核、代理查明细,三件事都要它。
只靠 `aff_quota` 一个数字做不到。

## 五、防滥用

规则第六条禁止自注册自消费,落到代码上:

```
□ inviter_id ≠ user_id
□ 向上遍历时记录已访问 id,成环即停
□ 注册 IP / 设备指纹去重(需另配)
□ 核查期内佣金 status=pending,可转额度但不可提现
```

⚠️ **当前无邮箱验证,注册零门槛,已有 11 个疑似机器人账号。**
现金提现是真金白银流出(返额度真实成本只有面值四成),上线前建议先补邮箱验证。

## 六、人工提现

规则定为人工办理、无门槛。最小实现:

```
代理侧   「推荐计划」页展示:可提余额、佣金明细、提现说明与微信号
平台侧   管理员在用户编辑页可扣减 aff_quota,并在流水表记一笔 status=withdrawn
```

管理员改 `aff_quota` 的能力目前**不存在**,需新增一个后台接口。
不做提现申请工单表 —— 走微信沟通,人工处理,够用。
